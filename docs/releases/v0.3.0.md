# Hermes Adaptive Effort v0.3.0 — preview

**Pre-release.** This is the first tagged release of Hermes Adaptive Effort. Interfaces and defaults may still change, and live validation is limited (see below). Routing stays **off** until you enable it.

Hermes Adaptive Effort is a Hermes plugin that asks a separate scorer to judge a task, then adjusts the reasoning effort of the outgoing model request. It is **fail-open**: if scoring fails, times out, or returns a value the route does not accept, the original request continues unchanged.

## Install

```bash
hermes plugins install 'atostivint/hermes-adaptive-effort' --enable
```

Then provide your scorer key, restart the serving Hermes process and run `/hae status`. See the [README](https://github.com/atostivint/hermes-adaptive-effort/blob/v0.3.0/README.md) and the [configuration guide](https://github.com/atostivint/hermes-adaptive-effort/blob/v0.3.0/docs/CONFIGURATION.md).

Enabling a routing mode authorizes sending bounded task text (default 4,000 characters) to the scorer you select.

## What this release contains

- **Four routing modes**: `off` (default), `auto`, `once`, `always`, with an independent subagent mode that also defaults to `off`.
- **Five scorer providers**: Jev (default), OpenAI Decisions, OpenRouter, Cloudflare Clef / Clef Flash, and a custom hosted or local endpoint (System One or Chat Completions format).
- **Route-specific effort choices** (new in 0.3.0): on exact registered routes the scorer picks directly from that route's allowed levels (for example `low/high/max` or `low/medium/high/xhigh/max`). Routes without a known vocabulary keep the numeric `0..2` score mapped to `low/medium/high`. One-level routes are fixed without a scorer call. A named answer outside the route's list fails open without a second scorer call.
- **Anthropic per-message effort continuity** (new in 0.3.0): limited to exact registered native models on `api.anthropic.com` when an `anthropic-beta` header is already exposed. Compression, missing anchors, manual setting changes, reset/eviction and errors invalidate continuity. Without the header, `auto` pins one decision per route.
- **Per-conversation history** (new in 0.3.0): a bounded journal of applied effort changes (at most 64 changes per conversation and 64 conversations) in the active Hermes profile. It stores effort transitions, model names and allowlisted decision metadata — never task or prompt text. A conversation reset clears its history. Available through `/hae`, the Dashboard and Desktop.
- **Desktop extension**: Effort chip with a compact routing-mode popup, recent changes for the focused chat, and aggregate activity. The chip now matches decisions by stored conversation ID rather than Desktop's temporary runtime ID.
- Opt-in target-model context for the scorer (`use_target_model_context`, off by default).
- Model-validation and Codex quota-audit tooling with the captured 2026-10-07 reports.
- MIT license.

## Contract changes

| Contract | Schema | Change |
| --- | --- | --- |
| Status | `hermes-adaptive-effort.status.v2` | Adds `decision_type` (`native_choice`, `legacy_score`, `fixed`), the route's `choices`, and `cache_behavior`. Named/fixed decisions report `score: null` and the chosen level in `label`. |
| Desktop decision event | `hermes-adaptive-effort.desktop-status.v2` | Same decision fields; adds `conversation_id`. `runtime_session_id` is kept as a compatibility alias carrying the stored ID. The Desktop reader accepts v1 and v2. |
| Conversation history | `hermes-adaptive-effort.history.v1` | New. `/hae history`, and `GET /history?conversation_id=…&limit=…` (limit clamped to 1–64; 503 on storage failure). |

Probe (`probe.v1`) and applied changes (`changes.v1`) are unchanged. No other API change is part of this release. Details: [Contracts](https://github.com/atostivint/hermes-adaptive-effort/blob/v0.3.0/docs/CONTRACTS.md).

## Validation status — read before relying on it

Automated checks: the Python test suite, the Node Desktop scenarios and Ruff pass locally and in CI for the tagged commit.

Live validation on 2026-10-07 used **deterministic local scores, not a real scorer**, against the OpenAI Codex/Responses route. A check mark means the exact effort value was observed in `reasoning.effort` at the HTTP boundary and a completed HTTP 200 response came back.

| Model | `low` | `medium` | `high` |
| --- | --- | --- | --- |
| `gpt-6.1-sol` | ✓ | ✓ | ✓ |
| `gpt-6-astra` | ✓ | ✓ | blocked |
| `gpt-6-luna` | blocked | blocked | ✓ |
| `gpt-5.6-terra` | blocked | ✓ | ✓ |
| `gpt-5.6-luna` | ✓ | ✓ | blocked |
| `gpt-6-sol` | blocked | blocked | blocked |
| `gpt-5.6-sol` | blocked | blocked | blocked |

- Only `gpt-6.1-sol` has complete evidence for all three values. "Blocked" means the final request body did not carry the chosen value, so no generation was sent; it is not a provider rejection.
- `xhigh`/`max`, Anthropic continuity, OpenCode Go and OpenRouter routes have **no live acceptance result** in this release; their behavior rests on local tests and vendor documentation.
- No result shows a change in internal reasoning budget, answer quality, cache benefit or cost saving. Classification adds latency and may add cost.

Full report (French): [live-20261007/report.md](https://github.com/atostivint/hermes-adaptive-effort/blob/v0.3.0/docs/validation/runs/live-20261007/report.md). Route-by-route evidence: [Model compatibility](https://github.com/atostivint/hermes-adaptive-effort/blob/v0.3.0/docs/MODEL_COMPATIBILITY.md).

## Upgrading

```bash
hermes plugins update hermes-adaptive-effort
```

Restart the serving agent and reconnect Desktop so the extension reloads. Already-running agent processes may keep emitting v1 Desktop events until restarted; the reader accepts both.
